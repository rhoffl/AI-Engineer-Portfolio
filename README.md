# Ron Hoffler — AI Engineer Portfolio

A curated evidence system, not a list of everything. The site makes one argument:

> Ron Hoffler designs, builds, evaluates, secures, and operates production AI systems across retrieval, agents, machine learning, data quality, model serving, and UAV cybersecurity.

## What's here

| Path | Purpose |
|---|---|
| `src/content/projects/*.json` | The six flagship case studies, one file each, all in the same eleven-section structure |
| `src/content/site.json` | Name, positioning, target roles, pillars, links, and the `draft` switch |
| `src/content/supporting.json` | Selected Engineering Work (supporting projects) |
| `src/content/ledger.json` | Evidence ledger: every public claim, its evidence, and its status |
| `src/content/research.json` | Doctoral UAV cybersecurity research page |
| `src/content/experience.json` | Experience areas mapped to projects, plus résumé roles |
| `src/types.ts` | The content model (`PortfolioProject`, `Metric`, `EvidenceLink`, …) |
| `portfolio/manifest.yaml`, `portfolio/evidence-ledger.yaml` | Generated by `npm run manifest` |
| `scripts/validate-content.mjs` | Content-accuracy rules (see below) |
| `scripts/check-site.mjs` | axe accessibility, phone/desktop overflow, light/dark, internal links |
| `templates/project-package/` | The standard layout every downloadable project repo should follow |
| `.github/workflows/ci.yml` | Validate → build → a11y/link checks → publish gate → GitHub Pages |

## Commands

```bash
npm install
npm run dev               # local preview with hot reload
npm run validate          # content checks; draft gaps are warnings
npm run build             # produces dist/index.html (single self-contained file)
npm run check:a11y        # accessibility + mobile + link checks on dist/
npm run manifest          # regenerate portfolio/*.yaml
npm run validate:publish  # strict: fails until every draft gap is resolved
```

## Status labels

Public labels: **Implemented** (working capability exists), **Measured** (repeatable test results exist), **Planned** (design or roadmap).

`unconfirmed` is a draft-only marker for anything not yet checked against its source package. It shows as a dashed "Confirm status" chip while `site.json` has `"draft": true`, and `validate:publish` fails while any remain.

## Rules the validator enforces

- A metric marked `measured` must have every field: dataset, model version, hardware/provider, test date, sample size, baseline, method, result, limitation.
- A `target` metric may not carry a result number.
- A project cannot be `measured`, or list measured results, without a measured metric behind it.
- The UAV project must carry its "research and simulation environment, not flight-safety-certified" notice.
- Publications need a venue and year, so unpublished work cannot be listed as published.
- Publish mode additionally requires: all statuses public, all evidence links filled, reproduction commands verified, contact links, location, research status, and résumé roles.

## Updating after a benchmark run

1. Open the project JSON, find the metric, set `"status": "measured"` and fill every field from the run.
2. Add the result to `results.measured`.
3. Change the ledger entry to `verified` and link the report in `evidence`.
4. `npm run validate && npm run manifest`.

## Stack note

The spec suggested Next.js + Tailwind. This build uses Vite + TypeScript with no UI framework and hand-written CSS tokens, so it compiles to one static HTML file that works on any host (or opened from disk) with no server. The content model and the content/presentation split are the same, so moving to Next.js later means rewriting the views and nothing else.

## Never commit

API keys, real customer information, private employer code, proprietary datasets, sensitive infrastructure details, or unsupported performance claims.
